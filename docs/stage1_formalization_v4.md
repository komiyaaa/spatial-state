# 段階1本体 完全定式化 v4(2026-08-25、μ(v)の投票箱統一を反映)

## 0. 本ドキュメントの位置づけ

v2(`stage1_formalization_v2.md`)では、$P_{occ}$(ログオッズ$\ell$)と
$\kappa$(確信度)を、**別々の式**として定式化していた。$\ell$の更新自体は
ベイズ更新そのものだったが、$\kappa$は`cons`・`dens`・`mob_signal`を
「それらしい重みで」組み合わせた、$\ell$とは独立に設計された式だった。

**v3は、$P_{occ}$と$\kappa$を、ベータ分布の2パラメータ$(\alpha,\beta)$
という、同じ1組の数字から両方とも導いた。** これにより、$\kappa$専用の
重み($w_{cons}, w_{dens}, w_{mob}$)が丸ごと不要になった。

**本v4での変更点**: v3では、柱2($\mu(v)$)だけが`transition_count/n_obs`
という単純な比率で、$\alpha,\beta$の投票箱とは独立した計算方法のまま
残っていた。これには$\gamma$のような忘却が無く、実験10で見つけた通り、
一度の誤判定が(縮みながらも)永久に傷として残る、という弱点があった。
**v4では、$\mu(v)$専用の投票箱$(\alpha_\mu,\beta_\mu)$を導入し(§2.2.1)、
$P_{occ}\cdot\kappa$と完全に同じ数式パターンに統一した。** これにより、
古い誤判定が正しく風化するようになり、$N_{min}$という硬い閾値も、
$\kappa$と同じ滑らかな信頼度$\kappa_\mu$に置き換わった。

**記号の衝突に関する注意**: v2では統合式の重みを$\alpha_1,\alpha_2,\alpha_3$と
呼んでいたが、本ドキュメントではベータ分布のパラメータ$\alpha$と紛らわしいため、
**統合式の重みは$w_1, w_2, w_3$に改名する**($\alpha_1\to w_1$、
$\alpha_2\to w_2$、$\alpha_3\to w_3$、意味は変わらない。これらの重み
自体は、§2.1.2〜2.1.3の検証を経て、最終的に不要と判明している)。

## 1. 記法

| 記号 | 意味 |
|---|---|
| $v$ | ボクセル(空間ID) |
| $t$ | 逐次的なスキャン通し番号(実時間ではない、`0,1,2,...,T-1`) |
| $c_t(v)$ | 時刻$t$でのボクセル$v$への点数(ヒット数) |
| $\alpha_t(v), \beta_t(v)$ | 時刻$t$時点の、ベータ分布の2パラメータ(仮想的な正・負の観測回数) |
| $P_{occ}(v,t)$ | 占有確率、$\alpha,\beta$から導出(§2.4) |
| $\kappa(v,t)$ | 確信度、$\alpha,\beta$から導出(§2.4) |
| $W$ | 柱3(窓+プーリング)の窓幅 |
| $\gamma$ | 忘却係数(過去の証拠をどれだけ引き継ぐか、$0<\gamma\leq 1$) |

## 2. 統一された更新式

### 2.1 柱1・柱3: 今回の証拠の強さ(§2.1.1・2.1.2・2.1.4・2.1.5・2.1.6・2.7.1で検算・修正)

$$
c_t^{eff}(v) = w_{fit}(v,t) \cdot c_t(v)
$$

**$w_{fit}$(パッチの位置合わせ品質、§2.7)は、最初のこの1箇所(実効点数)
にだけ掛ける。以降の$s_1$・ピーク判定・$h_W$は、すべてこの$c_t^{eff}$を
使う**(理由・経緯は§2.7.1で検算する。以前は$w_{fit}$を§2.3の証拠の式に
直接掛けていたが、それでは手遅れだった)。

$$
s_1(v,t) = w_{cnt}(c_t^{eff}(v)) = \min\left(1, \frac{\ln(1+c_t^{eff}(v))}{\ln(1+c_{sat})}\right) \in [0,1]
$$

$$
s_3(v,t) = \frac{H(v,t)}{H_{max}} \in [0,1], \qquad H(v,t) = \begin{cases}
h_W(v,t) + \sum_{u\in N_{r_{pool}}(v)} h_W(u,t) & (\text{is\_peak}(v,t)) \\
h_W(v,t) & (\text{otherwise})
\end{cases}
$$

**$s_3$は、$H_{max}$(窓×近傍の理論上の最大項数)で割っているため、実質的には
「合計」ではなく「平均」である**($H(v,t)/H_{max}$は、窓×近傍に含まれる
全項の平均値に等しい。§2.1.6で明示する)。

$$
\text{is\_peak}(v,t) = \mathbb{1}\left[C_W(v,t) \geq \max_{u\in N_{r_{pool}}(v)} C_W(u,t)\right], \qquad C_W(v,t)=\sum_{s=t-W+1}^{t} c_s^{eff}(v)
$$

**ピーク判定には、$w_{cnt}$で頭打ちさせる前の「実効累積点数$C_W$」を使う**
(理由は§2.1.6で検算する。頭打ちのある$h_W$を使うと、ピーク判定が
機能しなくなる場合があった)。

$$
h_W(v,t) = \sum_{s=t-W+1}^{t} w_{cnt}(c_s^{eff}(v)), \qquad H_{max}=W\cdot(1+|N_{r_{pool}}(v)|)
$$

($h_W$の総和範囲は「今回$t$を含む、直近$W$回分」である。理由は
§2.1.3で検算する。$\text{is\_peak}$による非極大抑制の理由は§2.1.4・2.1.5
で検算する)

#### 2.1.1 検算: 柱1と柱3は、同じ物差し($w_{cnt}$)を共有すべきである

**旧版(v2まで)の$h_W$は、$h_W(v,t)=\sum_{s} \mathbb{1}[c_s(v)>0]$、つまり
「1点でもヒットすれば1回とカウントする、二値の集計」だった。** これは
$s_1$が点数の濃さを連続的に扱っているのと、評価の粒度が食い違っている。

**検算**: $W=6$回のうち、毎回「1点だけのノイズ」が当たり続けた場合と、
毎回「30点の濃い壁」が当たり続けた場合を、旧版の$h_W$で比較すると、

```
ノイズ(毎回1点)   : h_W = 6/6
濃い壁(毎回30点) : h_W = 6/6   ← 全く同じ値になってしまう
```

**$s_1$では、この2つは$w_{cnt}(1)=0.289$ vs $w_{cnt}(30)=1.000$と、明確に
区別されているのに、$h_W$を経由した$s_3$では、この区別が消えてしまって
いた。**

**修正**: $h_W$の中身を、二値の集計ではなく、$s_1$と同じ$w_{cnt}$による
重み付き和に変更した(上記の定義式)。修正後、同じ検算をやり直すと、

```
ノイズ(毎回1点)   : h_W = 1.73/6
濃い壁(毎回30点) : h_W = 6.00/6   ← 濃さの違いが、正しく反映される
```

#### 2.1.2〜2.1.3 検算の経緯: s1は独立した項か、s3の材料か

**当初、「$h_W(v,t)$の総和に今回$t$自身を含めると、$s_1(v,t)$が$s_3(v,t)$
の内部に紛れ込み、$e^+=w_1 s_1+w_3 s_3$で二重に数えてしまう」という懸念
から、$h_W$の総和範囲を「今回を含まない、過去のみ」に修正したことが
あった。**

しかし、この修正には次の疑問が残った。**「$s_1$は、そもそも$s_3$から
独立した、もう1本の柱なのか。それとも、$s_3$を計算するための材料の
1つに過ぎないのか」。** 後者だとすれば、$s_1$を独立した項として別に
足すこと自体が、そもそも不要な複雑化だったことになる。

**検算**: 「$s_1$を独立させ、$s_3$からは今回を除く(旧修正)」場合と、
「$s_1$を独立させず、$s_3$(今回を含む)だけを使う(統合案)」場合とで、
確信度$\kappa$が閾値0.5に届くまでの速さを比較した。**当初、近傍の寄与を
計算に入れ忘れたまま比較し、統合案が100回経っても閾値に届かないという、
誤った結果を得た。近傍を正しく計算し直すと、**

```
統合案(s1を独立させない、s3(今回含む)だけ): kappa=0.5まで6回
旧修正(s1を独立させ、s3は今回を除く)      : kappa=0.5まで5回
```

**両者の差はわずか1回で、実質誤差の範囲だった。** つまり、$s_1$を独立
した項として別に足す理由は薄く、**$s_1$は$s_3$から独立した「もう1本の
柱」ではなく、$h_W$の中の1項として$s_3$に吸収される、材料の1つ**だと
結論づけた。$h_W$の総和範囲は、今回$t$を含む形に戻した(本節冒頭の
定義式)。

**この経緯自体が、良い教訓を含んでいる。** 一度目の検算(二重計上の
懸念)は、その場では筋が通っているように見えたが、より根本的な
「そもそも独立させる必要があるのか」という問いに立ち返ったことで、
より簡潔な設計にたどり着けた。逆に、その根本を確かめる2回目の検算では、
近傍の寄与を入れ忘れるという、単純だが見過ごしやすいミスも起きた
(検算自体も、間違えることがある)。

#### 2.1.4 検算: プーリングは、一度も証拠の無いボクセルにまで"滲み出す"か

**$e^+(v,t)=s_3(v,t)$には、`covered`のような歯止めが無い。** $H(v,t)$の
定義(近傍の$h_W$を足し込む)をそのまま使うと、**そのボクセル自身が
一度もヒットしていなくても、近傍(例えば壁)が繰り返しヒットするだけで、
$s_3$が正の値を持ち、$\alpha$が育ってしまう**のではないか、という懸念が
浮かんだ。

**検算**: あるボクセル$v$が、一度も自分自身ではヒットしないまま、
近傍(壁)だけが20回連続で濃くヒットし続けた場合を計算すると、

```
t= 0: P_occ=0.755, kappa=0.052
t= 8: P_occ=0.996, kappa=0.386
t=16: P_occ=1.000, kappa=0.444(まだ上昇中)
```

**$P_{occ}$がほぼ1.000まで育ってしまい、$\kappa$も0.5に向かって上昇し
続けていた。** このまま観測を続ければ、いずれ$\kappa_{th}$を超え、
**一度も証拠が無いボクセルが、隣の壁を理由に「占有」と誤って確定
してしまう**ところだった。

**原因**: プーリングは、本来「ドリフトのせいで、本当はこのボクセルに
当たるはずの点が、近傍にズレてしまった」ケースを救うために設計された。
これは、**そのボクセル自身に、最低でも過去1回は証拠があること**を
暗黙の前提にしている。一度も証拠が無いボクセルにまで、近傍の支持を
無条件に分け与えるのは、この前提を超えた「滲み出し」である。

**修正**: $H(v,t)$の近傍項に、$\mathbb{1}[\text{ever\_evidenced}(v)]$
というゲートを追加した(本節冒頭の定義式)。「そのボクセル自身が、
これまで一度でも証拠(ヒットまたは非存在判定の対象)を持ったことが
あるか」を確認し、無ければ近傍からの支持を一切加算しない。

修正後、同じ2つの状況を再検算すると、

```
ケースA(一度も自分がヒットしない、近傍だけがヒットし続ける):
  P_occ = 0.500(中立のまま)、kappaも上昇せず0に減衰していく
  → 正しく「情報が無い」という状態を保つ

ケースB(最初の1回だけ自分もヒットし、その後ドリフトで近傍にズレ続ける):
  P_occ = 0.838 → 0.997 → 0.999 と正しく育っていく
  → 本来のプーリングの目的(ドリフトの救済)は、変わらず機能する
```

**「一度も証拠が無い」ケースと「証拠はあるがドリフトで見失いがち」
ケースを、$\text{ever\_evidenced}(v)$1つのゲートで、正しく区別できる
ようになった…はずだった。**

#### 2.1.5 検算: ドリフトの範囲そのものが、丸ごと育ってしまわないか

**§2.1.4の修正には、まだ抜けがあった。** ドリフトによって、真の点が
毎回$\pm 1$ボクセルの範囲にランダムに散らばる場合、**その範囲内の
どのボクセルも、複数回のスキャンのうちに最低1回はヒットしてしまう。**
つまり$\text{ever\_evidenced}(v)$は、範囲内のすべてのボクセルで
真になり、結局「ドリフトの幅そのものが、丸ごと占有領域として育って
しまう」という、本質的には同じ問題が残っていた。

**確認**: 真の点が$x=0$にあり、ドリフトで$x\in\{-1,0,1\}$に散らばって
ヒットする場合、プーリング前の自己ヒット量を集計すると、

```
x=-1: h_W=5.00
x= 0: h_W=10.00  ← 真の中心が、自然と最も多くのヒットを集める
x= 1: h_W=5.00
```

**ドリフトは完全にランダムではなく、真の位置を中心とした分布になる
ため、「どのボクセルが一番濃くヒットしているか」自体が、真の位置を
教えてくれる。** これを活かし、**「近傍の中で自分が最大か」を判定し、
最大の時だけプーリングの恩恵を受ける(非極大抑制、Non-Maximum
Suppression)**という設計に改めた(本節冒頭の定義式、$\text{is\_peak}$)。

**検算(孤立点)**:

```
x=-1(非ピーク): s3=0.278(抑制される、確定に至らない水準)
x= 0(ピーク)  : s3=1.111(プーリングの恩恵を受け、確定に近づく)
x= 1(非ピーク): s3=0.278(抑制される)
```

**真の中心だけが育ち、ドリフトで巻き込まれただけの両隣は、抑制された
まま**になった。

**検算(連続した壁、心配されていたケース)**: 壁のように、隣接する
複数のボクセルすべてが「本物」として、同程度に濃くヒットし続ける
場合も確認した。

```
壁の外側(証拠なし): s3=0.000
壁面(x=0〜5、すべて本物): s3=1.111〜1.667、全てピーク判定 → 全て採用
壁の外側(証拠なし): s3=0.000
```

**壁のように面として連続する構造では、隣接するボクセルどうしが
$h_W$で同点(またはそれ以上)になるため、「自分が近傍の中で最大か
以上か」という判定(`>=`)により、面を構成する全ボクセルが正しく
ピーク判定される。** 孤立点では中心1つだけに絞り込み、連続面では
面全体を正しく残す、という、両方の要件を1つの判定式で満たせた。

**副次的な効果**: この`is\_peak`による判定は、§2.1.4で導入した
$\text{ever\_evidenced}$ゲートも不要にする。自分が一度もヒットして
いない($h_W(v,t)=0$)ボクセルは、近傍に何か証拠があれば自動的に
「非ピーク」(近傍の$h_W$の方が大きい)と判定され、$H(v,t)=h_W(v,t)=0$
のまま、正の証拠は発生しない。**1つの仕組み(非極大抑制)が、
「一度も証拠が無いボクセルへの滲み出し」と「ドリフト範囲そのものが
丸ごと育つ問題」の、両方を同時に解決した。**

#### 2.1.6 検算: $s_3$は合計か平均か、ピーク判定は何を使うべきか

**$H(v,t)$の分子は足し算(合計)だが、$H_{max}$(窓×近傍の理論上の
最大項数)で割っているため、$s_3$自体は実質的に「平均」である。**
$H(v,t)/H_{max}$は、窓×近傍に含まれる全項の平均値に等しく、近傍の
数が変わっても$s_3$の値域が$[0,1]$のまま保たれる。

**もう1つ、これまで検算していなかった点があった: ピーク判定
($\text{is\_peak}$)に、$h_W$(頭打ちのある$w_{cnt}$の積算)をそのまま
使ってよいか。**

**検算**: 真の中心(1回あたり平均28点、ノイズあり)と、ドリフトで
隣接する1マス(平均22点、僅差)を、30回分シミュレーションした。
$c_{sat}=10$のため、どちらの点数も$w_{cnt}$では早々に頭打ち(ほぼ1.0)
になり、**「どちらがより多く当たっているか」を$h_W$では区別できなく
なっていた**(頭打ちのせいで、僅差の比べ合いができない)。

**修正**: ピーク判定だけは、$w_{cnt}$で頭打ちさせる前の「生の累積点数
$C_W$」を使うことにした(本節冒頭の定義式)。**$w_{cnt}$の頭打ちは
「ノイズと本物を区別する」ための工夫だったが、その工夫が、今度は
「本物どうしの、僅差の比べ合い」を邪魔してしまっていた。証拠の
強さ($h_W$)には引き続き頭打りのある値を、ピーク判定($\text{is\_peak}$)
には頭打ちの無い生の値を使う、という役割分担にした。**

修正後、同じ状況を再検算すると、

```
ピークの入れ替わり(30回中): 10回(ノイズの重なりが大きいため、完全には無くならない)
真の中心(生28点)  : kappa=0.141
隣接(生22点、僅差): kappa=0.101
```

**入れ替わり自体はゼロにはならなかったが、真の中心の方が、統計的に
一貫して高い確信度に落ち着く傾向を確認した。** ノイズの重なりが大きい
場面では、判定が完全に安定するわけではないが、これは有限回の観測では
避けられない性質であり、回数を重ねるほど差は開いていくと考えられる。

### 2.2 柱2: 動的度合い(§2.2.1で投票箱方式に刷新)

**旧版(v2〜v3当初)の$\mu(v)$は、`transition_count/n_obs`という単純な
比率で、$\alpha,\beta$の仕組みとは完全に独立していた。** これには
$\gamma$のような忘却の仕組みが無く、実験10で見つけた通り、一度の
誤判定が永久に(縮みながらも)傷として残る、という弱点があった。

**修正: $\mu(v)$自身も、$P_{occ}$・$\kappa$と同じ「投票箱」の形式に
統一する。**

$$
\alpha_\mu(v,t) = \gamma_\mu\cdot\alpha_\mu(v,t-1) + \mathbb{1}[\text{今回、遷移が起きなかった}]
$$
$$
\beta_\mu(v,t) = \gamma_\mu\cdot\beta_\mu(v,t-1) + \mathbb{1}[\text{今回、遷移が起きた}]
$$
$$
\mu_{\text{raw}}(v,t) = \frac{\alpha_\mu(v,t)}{\alpha_\mu(v,t)+\beta_\mu(v,t)}
$$

$\gamma_\mu$: $\mu$専用の忘却係数(§2.2.1で検算する。$\gamma$と同じ値を
流用してもよいし、別途較正してもよい)。

**$N_{min}$による硬いゲートも、$\kappa$と同じ滑らかな信頼度に置き換える。**

$$
n_\mu(v,t) = \alpha_\mu(v,t)+\beta_\mu(v,t), \qquad
\kappa_\mu(v,t) = \frac{n_\mu(v,t)}{n_\mu(v,t)+n_{0,\mu}}
$$

$$
\mu(v,t) = \kappa_\mu(v,t)\cdot\mu_{\text{raw}}(v,t) + \big(1-\kappa_\mu(v,t)\big)\cdot 0.5
$$

**証拠(独立したセッション数)がまだ少ないうちは$\kappa_\mu\approx 0$
となり、$\mu$は中立の0.5に近い値を保つ。証拠が蓄積するにつれて
$\kappa_\mu\to 1$となり、$\mu$は$\mu_{\text{raw}}$そのものに近づく。**
これは、旧版の「$N_{min}$未満なら0.5、以上ならそのまま」という
硬い切り替えを、$\kappa$と全く同じ数式パターンで、滑らかにしたものである。

**この刷新により、$N_{min}$というパラメータは、$n_{0,\mu}$に置き換わる。**
硬い閾値が、$\kappa$系と同じ「仮想観測回数」の概念に統一されたことに
なる。

#### 2.2.1 検算: 投票箱方式は、傷を正しく風化させるか

### 2.3 正・負の証拠への分解(v2からの変更点、§2.1.2〜2.1.3を経て統合、§2.3.1で追加修正)

v2では$(s_1+s_3-1)$という1つの項の符号で正負を同時に表現していたが、
ベータ分布では**正の証拠は$\alpha$に、負の証拠は$\beta$に、別々に
積み上げる**必要があるため、ここで明示的に分ける。

**§2.1.2〜2.1.3の検算により、$s_1$を独立した項として別に持つ必要は
無いと分かった。** $s_1$は$h_W$(ひいては$s_3$)の中に、今回分の1項として
既に含まれている。したがって、正の証拠は$s_3$だけで表現する。

$$
e^{+}(v,t) = s_3(v,t)
$$

$$
e^{-}(v,t) = \mu(v) \cdot \max\big(0,\ 1-s_3(v,t)\big) \cdot \mathbb{1}[\text{covered}(v,t)] \cdot \mathbb{1}[\text{miss\_streak}(v,t) \geq M_{min}]
$$

$$
\text{miss\_streak}(v,t) = \begin{cases}
\text{miss\_streak}(v,t-1) + 1 & (\text{covered}(v,t) \ \wedge\ s_3(v,t)\approx 0) \\
0 & (\text{それ以外、何らかの支持があれば})
\end{cases}
$$

**「連続で何回、支持が無いままか」を数え、その回数が$M_{min}$に達する
まで、負の証拠を一切発生させない**(理由・検算は§2.3.1)。

$w_1, w_3$という2つの重みは、この統合により不要になった
(§7で削減後のパラメータ一覧を更新する)。

$\max(0,\cdot)$により、$s_1+s_3$が1を超える(強い正の証拠がある)場合は
$e^-=0$になる(v2の「柱2の項が自然に中立化する」という性質を維持)。

**$e^-$には、$e^+$のような重み($w_2$)を掛けていない。** これは単純化の
ためではなく、**§2.6で検証する通り、$e^+$と$e^-$それぞれの1ステップあたりの
最大値をどちらも1に揃えておかないと、$\kappa$(§2.4)が正・負どちらの証拠に
対しても公平に機能しなくなる、という実質的な要請**による。

#### 2.3.1 検算: 1回だけの測定ミスと、本当の撤去を区別する

**旧版は、$\text{covered}(v,t)$かつ$s_3(v,t)\approx 0$であれば、その場で
即座に$\mu(v)$に応じた負の証拠を発生させていた。** これには問題があった。
1回だけの見落とし(一時的な遮蔽・計測ミス)と、本当の撤去の初動を、
区別する材料が無かった。

**検算**: 長く安定していた静的な物体(μ=1.0)が、1回だけ見えなくなる
ケースと、その後も連続して見えなくなり続けるケースを比較した。

```
旧版(ゲート無し): 静的な物体が1回ミスしただけで、
                   P_occ = 0.999 → 0.781 まで急落してしまう
```

**これは、測定ミス・一時的な遮蔽の可能性を考えると、早まりすぎている。**

**修正**: 「連続で何回、支持が無いか」を数える`miss_streak`を導入し、
これが$M_{min}$(例: 2)に達するまでは、負の証拠を発生させないように
した。修正後、2つのケースを再検算すると、

```
ケースA(本当に1回だけの測定ミス、その後ヒットに戻る):
  ミス直後: P_occ = 0.999(不変、負の証拠なし)
  ヒットに戻った後: P_occ = 0.999(そのまま安定)
  → 誤って「消えた」と判定されることはない

ケースB(本当に撤去、その後も連続してミス):
  連続ミス1回目: P_occ = 0.999(まだ保留、M_min未満)
  連続ミス2回目: P_occ = 0.740(ここから負の証拠が働き始める)
  連続ミス3回目: P_occ = 0.559
  ...
  連続ミス8回目: P_occ = 0.159(正しく撤去に近づいていく)
```

**1回だけの見落としでは一切動じず、連続して見えなくなり続けた場合にのみ、
撤去の判定が進んでいくようになった。** これは、$\kappa$ゲート(§2.4・
§3)が「状態の確定」に複数回の一致を要求するのとは、**別の階層で機能する
安全装置**である。$\kappa$ゲートは「確定させてよいか」を判断するが、
`miss_streak`は「そもそも負の証拠を計上し始めてよいか」を判断する、
より手前の関門になっている。

### 2.4 ベータ分布パラメータの逐次更新

**注意(§5.7・§5.10・§5.11の経緯を経て、最終的にシンプルな形に
決着した): $\gamma$は、実際に経過した時間ではなく、観測回数(スキャンの
通し番号$t$が1つ進むごと)に応じて、一律で掛ける。** 一度は実時間に
応じた連続減衰($\gamma_{\text{eff}}=\gamma^{\Delta t/T_{unit}}$)を
導入したが、§5.11で「その区別が、実際にどれだけ重要か」を問い直した
結果、$\kappa$ゲート(複数回の一致を要求する仕組み)が既に持つ頑健さと
役割が重なっており、タイムスタンプへの依存を増やしてまで持つ価値は
無いと判断し、削除した。

$$
\alpha_t(v) = \gamma\cdot\alpha_{t-1}(v) + e^{+}(v,t), \qquad
\beta_t(v) = \gamma\cdot\beta_{t-1}(v) + e^{-}(v,t)
$$

初期値$\alpha_0(v), \beta_0(v)$は、`spatial_id_design_memo.md`の
`STRUCTURAL_LABEL_POLICY`(壁面・床面・天井面の事前分布)から与える
(§5.4で詳述)。$\gamma$(基準となる忘却係数)は、$\gamma=1$なら証拠を
無期限に積み続ける(v2までの設計はこれに相当)、$\gamma<1$なら
$\Delta t(v,t)$の長さに応じて、古い証拠が指数的に減衰する。

**$P_{occ}$と$\kappa$を、同じ$(\alpha,\beta)$から導く**:

$$
P_{occ}(v,t) = \frac{\alpha_t(v)}{\alpha_t(v)+\beta_t(v)}
$$

$$
\kappa(v,t) = \frac{n_t(v)}{n_t(v)+n_0}, \qquad n_t(v) = \alpha_t(v)+\beta_t(v)
$$

$n_0$: 確信度が0.5に達する仮想観測回数(1つの飽和パラメータ、$c_{sat}$と
同じ役割)。**これで、v2にあった$w_{cons}, w_{dens}, w_{mob}$という
3つの重みが不要になる。** 証拠を積むほど$n_t(v)$が増え、$\kappa$は
自動的に1に近づく。

### 2.5 この書き直しで削減されたパラメータ

| v2にあったもの | v3でどうなったか |
|---|---|
| $w_{cons}, w_{dens}, w_{mob}$(3つ、$\kappa$専用の重み) | 不要(§2.4、$\kappa$は$n_t(v)$だけの関数になった) |
| $\text{cons}(v,t)$の個別定義 | 不要(証拠の安定性は、$\gamma$による忘却と$n_t(v)$の大きさに、自然に織り込まれる) |
| $p_{th}$(占有判定の閾値、既定0.5) | 意味は残るが、ベータ分布の期待値がそのまま閾値と比較できるため、扱いはより自然になる |

新たに増えたパラメータは$\gamma$と$n_0$の2つのみ。差し引き、v2の10個から
7個程度まで削減できている(§7で正確に数え直す)。

### 2.6 検算: 撤去(OCCUPIED→DECAYED)が正しく反映されるか

**この定式化が「撤去」を正しく扱えるかは、当初は未検証だった。実際に
数値を動かして確認したところ、当初案(§2.3で$e^-$に$w_2$を掛けていた版)
には不具合があった。**

**不具合の内容**: $w_1+w_3=0.7$、$w_2=0.3$という非対称な重みのまま
$\gamma=0.8$でシミュレーションすると、

```
継続的にヒットする(占有され続ける)場合の定常状態: n=α+β → 3.05
継続的にMISSする(消失し続ける)場合の定常状態:     n=α+β → 1.50
```

**$\kappa=n/(n+n_0)$は$n$だけで決まるため、$n_0=3.0$のとき、占有継続時は
$\kappa$上限が0.504(かろうじて確定できる)だが、消失継続時は$\kappa$上限が
0.333までしか届かず、$\kappa_{th}=0.5$を永遠に超えられない。** つまり、
$P_{occ}$は正しく0.5を下回る(候補としてはDECAYEDになる)のに、
$\kappa$が確信度不足でCONFIRMEDまで到達せず、**永久にPENDINGのまま
DECAYEDが確定しない、という設計不備があった。**

**原因は、正の証拠の重み合計($w_1+w_3=1$)と、負の証拠の重み($w_2<1$)が
非対称だったこと。** §2.3の通り$w_2$を廃止し、$e^+$・$e^-$のどちらも
1ステップあたりの最大値を1に揃えたところ、

```
修正後、占有継続時の定常状態: n → 4.25、kappa上限 = 0.586
修正後、消失継続時の定常状態: n → 5.00、kappa上限 = 0.625
```

**両者がほぼ対称になり、DECAYEDも正しく確定できるようになった。**

さらに、「どれだけ長く占有されていたか」が、撤去検出の速さに影響しないか
($\gamma<1$による忘却が、この非依存性を保証するはずである)も確認した。

| 撤去前のヒット回数 | 撤去検出に必要なMISS回数($\gamma=0.8$) |
|---|---|
| 6回 | 5回 |
| 20回 | 5回 |
| 50回 | 5回 |
| 200回 | 5回 |

**長期間存在していたボクセルほど撤去を認識しにくくなる、ということは
無い(必要なMISS回数は一定に収束する)。** これは$\gamma<1$による忘却が、
狙い通り機能していることの裏付けである。

### 2.7 パッチワーク構築による、位置合わせ品質のばらつきへの対処

**背景**: 実際の構築方法は、複数のパッチ(高精度だが範囲は限定的な計測)を、
互いに直接繋ぐのではなく、**それぞれ独立してベースマップに位置合わせする**
方式である。これは、パッチを鎖のように直接繋ぐ方式に比べて、**誤差が
遠くのパッチへ蓄積しない**という利点がある(実際に検算し、鎖状では
平均2.48ボクセル分、ベースマップ経由では0.86ボクセル分に留まることを
確認した)。

ただし、**各パッチ単体の位置合わせ精度自体は、パッチごとにばらつく。**
$柱1$・$柱3$の証拠は、その証拠がどのパッチから来たかに関わらず、
これまで同じ重みで$\alpha,\beta$に加算していたが、**位置合わせが悪い
パッチからの証拠は、他より弱く扱うべきである。**

**利用できる情報**: VGICP(精密位置合わせ)は、既に`fitness_score`
(適合度、値が小さいほど良い)を計算済みである。ただし、`fitness_score`
は「位置合わせの正確さ」と「ベースマップの単純化による、そもそもの
形状の違い」を区別せずに混ぜてしまっている(平らな壁は単純化しやすく
`fitness_score`が良く出がち、複雑な形状は単純化により`fitness_score`が
悪く出がち、という構造ラベルによるクセがある)。**高精度な正解データ
(BLK360等)と比較して、このクセを差し引く方法も検討したが、そもそも
高精度機材が使えない屋内空間を対象にしている、という大前提と矛盾する
ため採用できない。**

**採用する方法**: `fitness_score`を絶対値としてではなく、**同じ構造
ラベルを持つ、他の多数のパッチの`fitness_score`と比べた相対値**として使う。
データが蓄積するにつれて、「そのラベルなら、だいたいこれくらいの値になる」
という相場が自然に見えてくるため、極端に相場から外れているパッチだけを
「本当に位置合わせが悪かった」とみなす。

$$
\tilde{f}(\text{label}) = \text{そのラベルを持つ過去のパッチの、fitness\_scoreの中央値}
$$

$$
w_{fit}(v,t) = \begin{cases}
1 & (n_{fit}(\text{label}(v)) < N_{fit,min}) \\
\min\left(1,\ \dfrac{\tilde{f}(\text{label}(v))}{f(v,t)}\right) & (n_{fit}(\text{label}(v)) \geq N_{fit,min})
\end{cases}
$$

$f(v,t)$: このボクセルの証拠を提供したパッチの、実際の`fitness_score`。
$n_{fit}(\text{label})$: そのラベルについて、これまで蓄積したパッチ数。
**$N_{fit,min}$未満のうちは、相場自体がまだ信頼できないため、
割り引きをかけない($w_{fit}=1$、§3の$\mu(v)$がPENDINGを扱うのと
同じ考え方)。**

**$w_{fit}$は、§2.3の証拠の式(最終段)にではなく、§2.1冒頭の
$c_t^{eff}(v)=w_{fit}(v,t)\cdot c_t(v)$という、一番最初の1箇所にだけ
掛ける。** 理由は§2.7.1で検算する。

$$
e^{+}(v,t) = s_3(v,t)
$$
$$
e^{-}(v,t) = \mu(v) \cdot \max\big(0,\ 1-s_3(v,t)\big) \cdot \mathbb{1}[\text{covered}(v,t)]
$$

**$e^+,e^-$自体には$w_{fit}$が直接出てこない(§2.3のまま)が、$s_3$の
計算に使われる$c_t^{eff}$を経由して、$w_{fit}$の効果は既に反映済みで
ある。**

**この仕組みは、柱1・柱2・柱3に続く「4本目の柱」ではなく、既存の
証拠に対する品質ゲートとして位置づける。** パッチ全体の位置合わせ品質は、
そのパッチ内の全ボクセルに共通して影響するため、個々のボクセル単位の
判定材料(柱1〜3)とは性質が異なる。

#### 2.7.1 検算: 品質チェックは、最初にやるべきか、最後にやるべきか

**当初、$w_{fit}$は§2.3の証拠の式($e^+,e^-$)に、最後に掛けていた。
つまり、$s_1$・ピーク判定・$h_W$は、すべて$w_{fit}$を考慮しない「生の
点数」のまま計算し、最後の最後に、結果をまとめて割り引く、という
順序だった。**

**この順序には見落としがあった。** ピーク判定(§2.1.5・2.1.6)は、
近傍どうしの「生の点数」を直接比べる仕組みである。もし、位置合わせの
悪いパッチ(低い`fitness_score`)が、たまたま高い生の点数を出して
しまった場合、**品質チェックがまだ適用される前の段階で、悪いパッチ由来の
ボクセルが、良いパッチ由来の隣接ボクセルとのピーク争いに、不当に
勝ってしまう**可能性があった。

**検算**: 良いパッチ由来のボクセル$v$(生の点数25点、$w_{fit}=1.0$)と、
悪いパッチ由来の隣接ボクセル$u$(生の点数35点、$w_{fit}=0.4$)を比較すると、

```
最後に品質チェックする場合: ピーク判定は生の点数だけで行う
  → v=25 vs u=35 → u(悪いパッチ由来)が、不当にピークとして選ばれてしまう

最初に品質チェックする場合: 実効点数(生の点数×w_fit)で比較する
  → v=25×1.0=25.0 vs u=35×0.4=14.0 → vが正しくピークとして選ばれる
```

**修正**: $w_{fit}$を、§2.3の証拠の式(最終段)ではなく、$c_t^{eff}(v)$
という、一番最初の入り口(本節冒頭の定義式)に移した。これにより、
$w_{fit}$の効果が、ピーク判定を含む、以降のすべての計算に一貫して
反映されるようになった。**「最後にまとめて品質チェックする」のではなく、
「最初に品質を織り込んでから、その後は同じ計算を通す」方が、途中の
判定(特にピーク判定のような、値どうしを直接比べる処理)を歪めない**、
という教訓を得た。

## 4. まとめ: 完全な処理フロー(v4版)

```
1. c_t(v)を観測する
2. f(v,t)(このボクセルの証拠元パッチのfitness_score)から、w_fit(v,t)を計算する(§2.7)
3. c_t^eff(v) = w_fit(v,t)・c_t(v) を計算する(§2.7.1、品質チェックを最初に適用)
4. s_1(v,t), s_3(v,t) を、c_t^effを使って計算する(柱1・柱3、§2.1)
5. covered(v,t) を判定する
6. μ(v) を計算する(柱2、§2.2.1、alpha_mu・beta_muの投票箱から導出)
7. miss_streak(v,t) を更新する(§2.3.1、連続で支持が無い回数を数える)
8. e^+(v,t), e^-(v,t) を計算する(§2.3、e^-はmiss_streak>=M_minの時だけ発生)
9. α_t(v) = γ・α_{t-1}(v) + e^+、β_t(v) = γ・β_{t-1}(v) + e^- を更新する(§2.4)
10. P_occ(v,t) = α_t(v)/(α_t(v)+β_t(v))
11. κ(v,t) = n_t(v)/(n_t(v)+n_0)、n_t(v)=α_t(v)+β_t(v)
12. κ(v,t)とκ_thを比較し、(state_t(v), confidence_flag_t(v))を確定する(§3)
13. $\text{state}_t(v)$が確定状態(OCCUPIED/DECAYED)の間で切り替わった場合
    (OCCUPIED→DECAYED、DECAYED→OCCUPIEDのどちらの向きでも)、
    alpha_mu(v)・beta_mu(v)の投票箱を更新する(§2.2.1。片方向だけを
    数えると、設置・撤去を繰り返す動的な物体の$\mu(v)$が誤って
    高く(静的寄りに)出る不具合があった、§5.6で検証済み)
```

v2の10ステップから、$w_{fit}$を最初に適用する2ステップ(2〜3)と、
`miss_streak`を数える1ステップ(7)が増えた。ステップ13は、v3までの
`transition_count`単純カウントから、v4で$\mu$専用の投票箱更新に
置き換わっている(§2.2.1)。これ以外は、if文を含まない$(\alpha,\beta)$の
更新と、その比だけの計算に単純化されている。

## 5. 逆算: この定式化が要求する点群データの性質(v3で更新)

### 5.1 v2からの主な変更点

v2の逆算(v2 §7)は、$W, r_{pool}, N_{min}, \theta_{static}$を中心に整理して
いた。v3では$\theta_{static}$が既に不要になっている(§2.2は変更なし)ため
そのまま引き継げるが、新しく増えた$\gamma$(忘却係数)・$n_0$(確信度の
飽和点)について、要求されるデータの性質を新たに考える必要がある。

### 5.2 γ(忘却係数)が要求するもの

$\gamma$は、「過去の証拠を、どれだけ先まで信じ続けるか」を決める。これを
意味のある値に較正するには、**「本当に状態が変化した瞬間」を含むデータが
必須**である。

```
γが大きすぎる(1に近い)場合の問題:
  一度OCCUPIEDと確定したボクセルは、その後何回MISSしても、
  αが大きいままβがなかなか追いつかず、DECAYEDへの反映が遅れる
  → 「本当に消えたのに、いつまでも消えたと認識しない」という失敗

γが小さすぎる場合の問題:
  少し観測が途切れただけで、蓄積した証拠(α)がすぐに薄まってしまう
  → パッチワーク計測で「今回たまたま見ていないだけ」の場所を、
    誤って不確かと判定してしまう
```

この2つの失敗モードのどちらにも転ばない$\gamma$を較正するには、
「設置されたまま長期間安定していたボクセル」と「実際に撤去された
ボクセル」の、両方を含む長期データが要る。これはv2の§7.1で既に
指摘した「複数セッションデータが必要」という結論と、同じ方向を指すが、
**$\gamma$の較正は、単に複数回観測するだけでなく、「観測の間隔(どれだけ
時間を空けて再訪したか)」の記録も必要とする**、という点で、より
具体的な要求になっている。

**実際に簡易検算した結果、この懸念は仮説ではなく実際に起きることを確認した。**
静的な物体(6回濃いヒット→6回連続MISS)に対して、$\gamma$を変えて
$P_{occ}$の下がり方を見ると、

| $\gamma$ | 消失後の$P_{occ}$ |
|---|---|
| 1.0(忘却なし) | 0.664(閾値0.5を上回ったまま、DECAYEDに反映されない) |
| 0.9 | 0.519(ぎりぎり反映されない) |
| 0.8 | 0.349(反映される) |
| 0.7 | 0.194(明確に反映される) |

**$\gamma=1$(v2までの、忘却の無いログオッズ累積と等価)のままでは、
実際に消失が正しく検出できないことが、検算で確認された。** つまり
$\gamma<1$への変更は、v3の理論的な整理のついでではなく、**実用上
必須の変更**だったと言える。

### 5.3 n_0(確信度の飽和点)が要求するもの

$n_0$は、「何回分の仮想観測で、確信度が0.5に達するか」を決める。これを
較正するには、「明らかに確信してよいはずの場面」と「明らかにまだ
確信すべきでない場面」の両方の実例が要る(例: 壁のように、5回程度
観測すれば人間なら「もう明らかにある」と判断する場所。これは既存の
E1〜E3データでも検証できる)。

#### 5.3.1 検算: γ・n_0・κ_thには、超えてはいけない理論上限がある

**継続的にヒットし続けた場合、$n_t(v)=\alpha_t(v)+\beta_t(v)$は無限には
育たず、$\gamma$による減衰の効果で、ある一定値に収束する(等比級数の和)。**

$$
n_{\text{steady}} = \frac{1}{1-\gamma}
$$

**この収束値が、$\kappa$が到達できる「理論上の天井」を決める。**

$$
\kappa_{\max} = \frac{n_{\text{steady}}}{n_{\text{steady}}+n_0} = \frac{1}{1+n_0(1-\gamma)}
$$

**$\kappa_{\max} < \kappa_{th}$であれば、どれだけ観測を重ねても
(理論上、無限回観測しても)、状態は永久にCONFIRMEDへ到達できない。**
これは実装上のバグではなく、パラメータの組み合わせ次第で起こりうる、
純粋に数学的な制約である。$\kappa_{\max}\geq\kappa_{th}$を解くと、

$$
n_0 < \frac{1-\kappa_{th}}{\kappa_{th}(1-\gamma)}
$$

**という、$n_0$の上限が導かれる。** 実際に数値を当てはめると、

| $\gamma$ | $\kappa_{th}=0.4$ | $\kappa_{th}=0.5$ | $\kappa_{th}=0.6$ |
|---|---|---|---|
| 0.6 | $n_0<3.75$ | $n_0<2.50$ | $n_0<1.67$ |
| 0.7 | $n_0<5.00$ | $n_0<3.33$ | $n_0<2.22$ |
| 0.8 | $n_0<7.50$ | $n_0<5.00$ | $n_0<3.33$ |
| 0.9 | $n_0<15.00$ | $n_0<10.00$ | $n_0<6.67$ |

**この表から、$\gamma$を小さくする(忘れやすくする)ほど、$n_0$に
許される余地が狭くなることが分かる。** §5.7で見た「$\gamma$は
小さいほど、撤去の検出が速い」という利点と、この「$\gamma$が小さいと
$n_0$の余地が狭まる」という制約は、**トレードオフの関係にある。**
どちらも都合よく設定することはできず、**$\gamma$を先に決めてから、
その$\gamma$のもとで$n_0$の上限を計算し、その範囲内で$n_0$・$\kappa_{th}$
を選ぶ、という順序で較正する必要がある。**

**この制約は、フェーズ3(較正)における最大のリスクである。** もし
$\gamma, n_0, \kappa_{th}$を、この制約を意識せずに個別に較正してしまうと、
「状態が一切CONFIRMEDにならない」という、原因の分かりにくい不具合に
陥る危険がある。較正作業に着手する前に、**まず$\gamma$の候補値を決め、
上記の式で$n_0$の許容範囲を先に計算しておく**ことを推奨する。

### 5.4 事前分布(α_0,β_0)と、構造ラベルの接続

v3で初めて、`spatial_id_design_memo.md`の`STRUCTURAL_LABEL_POLICY`
(壁面・床面・天井面の事前分布、`prior_pseudo_count`)と、この定式化が
数式のレベルで正確に接続した。

**【§5.9との接続で発見・修正】ベースマップ自体の解像度と、状態管理用の
$\text{zoom}^*$(§5.9、ドリフト耐性のために粗く取る)は別物であり、
単純にラベルを転記すると不具合が起きる。** 壁のように薄い構造物は、
$\text{zoom}^*$の1ボクセルの中に「半分だけ壁、半分だけ空間」という
形で収まることがあるため、「ボクセル中心が壁の内側かどうか」という
単純な判定では、**重なりの度合いを無視した、不連続な誤判定**が起きる。

**検算**: 壁厚15cm、ボクセルサイズ30cmの断面で、ボクセル中心を壁から
少しずつ離していくと、

| ボクセル中心と壁の距離 | 実際の重なり率 | 中心判定の結果 |
|---|---|---|
| 0〜15cm | 50% | 壁 |
| 20cm | 33% | 非壁 |
| 25cm | 17% | 非壁 |

**「中心が壁の外に出た瞬間」(20cm地点)でも、実際にはまだ33%重なって
いるのに、判定は連続性を無視して「非壁」に切り替わってしまう。**

**修正**: $\alpha_0, \beta_0$に、ベースマップ(その空間の最も細かい
解像度)から計算した、$\text{zoom}^*$ボクセルとの体積重なり率
$f_{overlap}(v)\in[0,1]$を掛ける。

$$
\alpha_0(v) = \text{prior\_pseudo\_count}(\text{label}(v)) \cdot p_{prior}(\text{label}(v)) \cdot f_{overlap}(v)
$$
$$
\beta_0(v) = \text{prior\_pseudo\_count}(\text{label}(v)) \cdot \big(1-p_{prior}(\text{label}(v))\big) \cdot f_{overlap}(v)
$$

($p_{prior}$: そのラベルの「最初から占有と仮定してよい度合い」、壁面・
床面ならほぼ1に近い値。$f_{overlap}(v)=0$なら、その構造ラベルの影響を
一切受けない中立の事前分布になる)

これが要求するデータは、**ベースマップが、$\text{zoom}^*$より十分に
細かい解像度で保持されていること**(でなければ$f_{overlap}$自体を
計算できない)。加えて、以前の設計議論(床面はかなり正確、壁面・
天井面は単純化されている)が、そのまま$\text{prior\_pseudo\_count}$の
値の妥当性検証に直結する。

### 5.5 理想的な点群データの要件(v3、更新版)

```
① 1回のセッション内: v2から変更なし(密度・空間的まとまり)
② セッション間: 同じ空間IDを複数回再訪すること(v2から変更なし)
③【v3で追加→§5.11で不要と判明】再訪の「間隔」の記録は、当初必須と
   考えていたが、γ_effの廃止(§5.11)により、最終的には不要になった。
   観測回数だけを使うシンプルな設計で、実用上は十分だと判断した
④【v3で追加】長期間安定していたボクセルと、実際に変化したボクセルの
   両方が、区別できる形でデータに含まれること(γの2つの失敗モードを
   両方検出するため)
⑤【v3で明確化、§5.4末尾で追加修正】ベースマップの構造ラベル(壁面・
   床面・天井面)の精度が、既知であること(prior_pseudo_countの妥当性
   検証のため)。**加えて、ベースマップ自体が、状態管理用のzoom*より
   十分細かい解像度で保持されていること**(f_overlapの計算に必須。
   ベースマップの解像度がzoom*と同程度以下だと、重なり率という
   概念自体が意味をなさない)
⑥【§2.6の検証で追加】「占有が確定するまでの過程」と「撤去が確定する
   までの過程」の、両方を記録したデータであること。§2.6で見つかった
   κの非対称性のような不具合は、片方(占有側)だけを見ていては
   気づけず、撤去側も同じ解像度で記録して初めて発見できた
⑦【§5.8・5.9の検証で追加】柱2・柱3が扱う「状態」のボクセルサイズが、
   実際のドリフト誤差に対して十分粗いこと。**ただし、これはズーム
   レベルの番号ではなく、物理サイズ(cm)で決める。** unit-sizeは
   空間ごとに異なるため、「zoom=7を使う」のような固定の番号指定は
   空間をまたいで通用しない。目標物理サイズを先に決め、空間ごとに
   その空間自身のunit-sizeテーブルから該当するズームレベルを
   逆引きする(§5.9の$\text{zoom}^*$)
```

**③・④・⑥・⑦が、v2の逆算には無かった、v3で新たに見えてきた要件である。**
「複数回観測すればよい」ではなく、「いつ・どれだけの間隔で観測したか」
「占有と撤去、両方の過程を同じ解像度で記録したか」「ボクセルサイズが
実際の計測誤差に見合っているか」まで踏み込む必要がある、という、
より具体的な要求になった。

### 5.6 検算: 動的な物体(繰り返し設置・撤去)を、正しく動的と判定できるか

**§2.6は「静的な物体が消える」ケースだけを見ていた。「繰り返し設置・
撤去される、本当に動的な物体」を正しく動的と判定できるかは、別途
検証が必要だった。**

**見つかった不具合**: 処理フロー(§4)のステップ10は、当初
「OCCUPIED→DECAYEDに変わった時だけ`transition_count`を+1する」という、
**片方向だけのカウント**だった。5回設置・5回撤去を繰り返す(明らかに
動的な)物体で検算すると、$\mu(v)$が0.90〜0.92に収束し、**「かなり
静的」という、明らかに誤った判定になっていた。**

**修正**: OCCUPIED→DECAYED・DECAYED→OCCUPIEDの**両方向**を
`transition_count`に数えるよう修正した(§4ステップ10)。修正後、
同じ動的な物体で$\mu(v)$は0.82〜0.84まで下がった(静的な物体は、
修正前後どちらも正しく1.0のまま)。

**さらに見つかった、定義上の限界**: 修正後も$\mu(v)=0.82$は、
「50%の時間帯で存在しない」という直感的な動的さに比べると、まだ
高めに見える。原因を検算すると、これは不具合ではなく、
$r_{trans}=\text{transition\_count}/n_{obs}$という**定義そのものの
性質**だった。

```
5回オン・5回オフの周期を4周(観測40回)した場合:
  実際に状態が切り替わる「遷移の瞬間」は、1周期あたり2回、
  合計8回だけ(残り32回は、オンまたはオフが安定して続いている観測)
  r_trans = 8/40 = 0.2、mu = 1 - 0.2 = 0.8
```

**「観測回数のうち何回が遷移の瞬間だったか」という定義は、周期が短い
(頻繁に切り替わる)物体ほど$r_{trans}$が上がるが、「存在する時間の
割合」のような、別の直感的な動的さの指標とは、必ずしも一致しない。**
これは実装上のバグではなく、$r_{trans}$という指標が持つ、設計上の
限界として記録しておく。**新規データでの較正時(§7)は、$\mu(v)$の
数値そのものよりも、「相対的に、より動的な物体ほど$\mu(v)$が
低く出ているか」という順序関係が保たれているかを、重点的に確認する
必要がある。**

### 5.7 検算: γは、間隔の長さを無視していないか

**§5.2で「$\gamma$の較正には、再訪の間隔記録が必要」と指摘していたが、
実際に検算すると、当時のままの式($\gamma$を$t$が1つ進むごとに一律で
掛ける)は、この間隔をどこにも使っていなかった。** 要件として書いた
ことと、実際の式が食い違っていた。

**検算内容**: 3回観測して占有と分かったボクセルが、その後1回だけ
非ヒットになるケースを2通り試した。「4回目の観測が、3回目から**1日後**
だった場合」と「4回目の観測が、3回目から**6ヶ月後**だった場合」で、
当初の式ではどちらも$P_{occ}=0.620$と、**全く同じ結果になってしまう**
ことを確認した。1日後のたった1回の非ヒットと、6ヶ月間放置された末の
1回の非ヒットが、同じ重みで扱われるのは明らかにおかしい。

**修正**: §2.4の通り、$\gamma$を$t$が1つ進むごとに一律で掛けるのではなく、
実際に経過した時間$\Delta t(v,t)$に応じて連続的に減衰する
$\gamma_{\text{eff}}(v,t)=\gamma^{\Delta t(v,t)/T_{unit}}$に差し替えた。
修正後、1日後の非ヒットは$P_{occ}=0.620$のまま(ほぼ変わらず)、6ヶ月後の
非ヒットは$P_{occ}\approx 0.000$(以前の証拠がほぼ完全に減衰し、直近の
非ヒットが支配的になる)と、**明確に区別されるようになった。**

**これは、v2から引き継いだ「$t$は実時間ではなく通し番号」という前提
(§1)を、$\gamma$の設計に反映し忘れていたことが原因だった。** 逆算
(§5.2)で要件としては認識していたのに、数式に落とし込む段階で
抜け落ちていた、という点で、これまでで一番「頭では分かっていたのに
式に反映し忘れていた」に近い種類の不具合だった。

### 5.8 検算: 位置誤差(ドリフト)は、どこまで許容できるか

**§2.6〜5.7は、いずれも「ヒットしたか否か」だけを動かす検算だった。
iPhoneのLiDARには、ドリフトによる位置誤差(点群自体が真の位置から
ずれる)が別途あり、これはこれまで検算していなかった。** これは、
そもそも柱3(時間窓+近傍プーリング)を設計した動機そのものである
(「スマホで計測した点群は、ドリフトの影響により計測誤差が発生し、
毎回別のボクセルに点が当たってしまう」)。

**モンテカルロシミュレーション**: 真に静的な物体(注目ボクセル$v=0$)に
対し、ドリフトにより、実際に点が当たるボクセルが毎回$v=0$から
$\sigma_{err}$(標準偏差、ボクセル単位)だけランダムにずれる、という
状況を15回分の観測でシミュレーションし、$r_{pool}$を変えて$v=0$の
$P_{occ}$を比較した。

| 誤差$\sigma_{err}$(ボクセル単位) | $r_{pool}=0$ | $r_{pool}=1$ | $r_{pool}=2$ |
|---|---|---|---|
| 0.0(誤差無し) | 1.00 | 1.00 | 1.00 |
| 0.5 | 0.71 | 0.93 | 0.93 |
| 1.0 | 0.25(誤判定) | 0.62 | 0.78 |
| 1.5 | 0.11(誤判定) | 0.49(境界線) | 0.72 |
| 2.0 | 0.11(誤判定) | 0.38(誤判定) | 0.50(境界線) |
| 3.0 | 0.02(誤判定) | 0.14(誤判定) | 0.37(誤判定) |

**プーリング無し($r_{pool}=0$)では、誤差がわずか0.5ボクセル分あるだけで
既に不安定になり、1ボクセル分の誤差で完全に破綻する。** これは、
柱3(プーリング)が「あれば望ましい」機能ではなく、**iPhoneの精度では
無いと成立しない、必須の機能である**ことを裏付けている。**目安として、
$r_{pool}$は、想定される位置誤差$\sigma_{err}$(ボクセル単位)と同じか、
それ以上である必要がある。**

**実測のドリフト誤差と、ボクセルの物理サイズを突き合わせる**
(以前の予備検証で得ていた「ARKit drift leaving only 7.9% stable voxels
even at 16cm resolution」という知見から、誤差の目安を16cmとして計算):

| ボクセルの物理サイズ | 誤差$\sigma_{err}$(ボクセル単位換算) | 判定 |
|---|---|---|
| 40cm | 約0.40 | 安全圏($r_{pool}=1$で十分) |
| 20cm | 約0.80 | 安全圏 |
| 10cm | **約1.60** | **危険域($r_{pool}=1$は境界線、2でも厳しい)** |

**これまでG002v3.jsonの例で「10cm」を細かい解像度の例として扱ってきたが、
この解像度でiPhone計測を使う場合、ドリフト誤差だけで$r_{pool}$が
破綻しかねない水準にあることが分かった。** より粗い物理サイズ
(20〜40cm程度)であれば、既存の$r_{pool}=1\sim2$の設計でも十分安全に
機能する。

**【重要な訂正】この表は「ズームレベルの番号」ではなく「物理サイズ」を
基準に読む必要がある。** `spatial_id_design_memo.md`で確認した通り、
`unit-size`(ズームレベルとボクセルサイズの対応)は、**ローカル空間
ごとに個別に定義される**(空間の実測footprintから、都度導出される)。
したがって、「zoom=7を使えば安全」というような、ズームレベルの番号
そのものを固定した助言は、空間によっては成立しない
(下記§5.9で実際に検算する)。

### 5.9 検算: ズームレベルの番号は、空間をまたいで使い回せない

$$
\text{空間A}(\text{footprint}\approx 46\text{m}):\ \{0:51.2,\ 1:25.6,\ \dots,\ 7:0.4,\ 8:0.2,\ 9:0.1\}\ (\text{全10段})
$$
$$
\text{空間B}(\text{footprint}\approx 6\text{m}):\ \{0:6.4,\ 1:3.2,\ \dots,\ 5:0.2,\ 6:0.1\}\ (\text{全7段})
$$

**空間Aの`zoom=7`は40cmだが、空間Bには`zoom=7`自体が存在しない**
(最大でも`zoom=6`(10cm)まで)。「状態管理はzoom=7〜8を使う」という
ような、**ズームレベルの番号を固定した指示は、空間ごとに`unit-size`の
段数が違う以上、成立しない。**

**正しい設計**: 目標とする物理サイズ(例: 30cm、§5.8のドリフト誤差から
安全側に決める)を先に固定し、**各ローカル空間ごとに、その空間自身の
`unit-size`テーブルから、目標に一番近いズームレベルを逆引きする。**

$$
\text{zoom}^*(\text{space}) = \underset{z}{\arg\min}\ \big|\ \text{unit-size}(\text{space})[z] - \text{target\_physical\_cm}\ \big|
$$

実際に計算すると、目標30cmに対して、空間Aは`zoom=7`(40cm)、空間Bは
`zoom=4`(40cm)が最も近く、**番号は違うが、選ばれる物理サイズはどちらも
40cmで揃う**(番号ではなく物理サイズで考えれば、空間をまたいでも
一貫した基準になる)。

**結論**: 「状態管理に使うズームレベルは、空間ごとに、目標物理サイズ
(ドリフト誤差から安全に決めた値、目安30cm前後)へ$\text{zoom}^*$で
逆引きして決める」という設計に修正する。固定のズームレベル番号を
使い回すのは、`unit-size`が空間ごとに可変であるという、この設計の
根本前提(spatial_id_design_memo.md)に反する。

### 5.10 設計判断: タイムスタンプが無い(信頼できない)場合のフォールバック

**§5.7で「$1$日後」と「$6$ヶ月後」を区別できるようにしたが、これは
正確なタイムスタンプが取得できることが前提だった。** 実際に計測された
点群データそのものには、タイムスタンプが付与されていない、または
信頼できない場合がある。この前提が崩れた時にどうするかを、ここで
明示的に決めておく。

**方針**: タイムスタンプが利用できない場合は、$\gamma_{\text{eff}}$を
$\Delta t/T_{unit}=1$(1回の観測を「1単位の経過」とみなす)に固定した、
単純なカウントベースの式にフォールバックする(§2.4)。**これは、
v2までの「$t$が1つ進むごとに一律で$\gamma$を掛ける」という、最初の
(不完全だった)設計と、数式としては同じものに戻る。**

**この設計判断が意味すること**:

```
利点: タイムスタンプの有無・信頼性に関わらず、必ず動く
      (「ボクセル内に何回分のデータが積み上がっているか」という、
       最も基本的な情報だけで機能する)

代償: §5.7で解決したはずの「1日後」と「6ヶ月後」の区別が、
      再びできなくなる(この2つは、タイムスタンプが無い場合、
      見分けようがない)
```

**この代償は、$\gamma$の較正方針にも影響する。** タイムスタンプに
頼れない前提で$\gamma$を較正するなら、$\gamma$の値は「典型的な再訪
間隔(観測どうしの間に、平均してどれくらいの時間が空くか)」を
織り込んだ、やや保守的な値にしておく必要がある(間隔が短い運用を
想定した$\gamma$を、間隔が長い運用にそのまま使うと、§5.7で見つけた
問題が形を変えて再発する)。

**§5.5の要件③(再訪の間隔記録)の位置づけの変更**: 以前は「必須」と
書いていたが、この時点では「あれば、より精密な$\gamma_{\text{eff}}$が
使える」という任意の強化要素に格下げしていた。**ただし、§5.11で
この二段構え自体を見直し、最終的に$\gamma_{\text{eff}}$を廃止したため、
この要件は完全に不要になった(現行の§5.5には反映済み)。**

### 5.11 設計判断の再考: そもそも「1日後 vs 6ヶ月後」の区別は必要か

**§5.10までは、「タイムスタンプが使えるなら精密に、使えなければ
簡易に」という、2つの式を使い分ける設計だった。ここで一度立ち止まり、
そもそも$\gamma_{\text{eff}}$(時間に応じた精密な減衰)が、この用途に
本当に必要かを問い直した。**

**再考の要点**:

1. **$\kappa$ゲートと役割が重なる**: 状態確定には、そもそも$\kappa$
   (確信度)が閾値を超える必要があり、これは「複数回、一致した証拠が
   積み重なること」を要求する仕組みである。1回のミスだけで状態が
   変わることは、時間の情報を使う・使わないに関わらず、元々起きない。
   $\gamma_{\text{eff}}$が防ごうとしていた「1回のミスで早まって判定
   する」問題は、$\kappa$ゲートが既にかなりの部分をカバりしていた。

2. **タイムスタンプへの依存を、そもそも避ける方針にしていた**: §5.10で
   「タイムスタンプが無くても動く」ことを重視する方針に決めたばかり
   であり、$\gamma_{\text{eff}}$の恩恵(精密な時間減衰)を実際に
   使える場面は、最初から限定的だと分かっていた。

3. **パラメータが1つ減る**: $T_{unit}$という、較正が必要なパラメータを
   丸ごと削除できる。

**結論**: $\gamma_{\text{eff}}$(実時間に応じた連続減衰)を廃止し、
§2.4を、観測回数だけに応じた単純な$\gamma$(v2までの、最初の設計と
同じ形)に戻す。**「1日後」と「6ヶ月後」を区別できないという代償は
残るが、この代償は、$\kappa$ゲートが持つ頑健さで、実用上ほぼ
補われていると判断した。**

**この一連の経緯(§5.7で複雑にし、§5.10で二段構えにし、§5.11で単純に
戻した)自体が、記録しておく価値のある教訓だと思う。** 「区別できない
より、区別できた方が良いはずだ」という直感だけで複雑さを足すのではなく、
「その区別は、既にある他の仕組みと比べて、どれだけの価値を追加している
か」を都度問い直すことで、最終的には最初の設計に近い、しかしより
意図の明確な形に戻ってきた。

### 5.12 シミュレーションによる、具体的な収集計画の設計

**これまでの§5全体で、断片的に「こういうデータが必要」と述べてきたが、
ここで1つの具体的な収集計画として統合し、主要パラメータについては
実際にシミュレーションして、必要な回数を数値で求める。**

#### 5.12.1 $N_{min}$(§2.2、$\mu(v)$がPENDINGを脱する観測回数)

**【注記】本節は、§2.2.1で$\mu(v)$を投票箱方式に刷新する前の、
旧設計($N_{min}$による硬いゲート)を対象にしたシミュレーションである。**
傾向(必要な再訪回数のオーダー)は刷新後も参考になるが、刷新後の
$n_{0,\mu}$の較正には、同様のシミュレーションを$\kappa_\mu$方式で
再実施することが望ましい。

**シミュレーション**: 静的な物体(遷移率ほぼ0)と動的な物体(1回の観測で
30%の確率で状態反転)を、$N_{min}$回observationした場合の$\mu(v)$の
ばらつきと、閾値0.85での誤分類率を比較した。

| $N_{min}$ | 静的側 誤分類率 | 動的側 誤分類率 | 標準偏差(静的/動的) |
|---|---|---|---|
| 3 | 5.6% | 35.4% | 0.081 / 0.264 |
| 5 | 11.0% | 14.6% | 0.068 / 0.202 |
| 8 | 0.6% | 25.8% | 0.046 / 0.152 |
| 12 | 1.6% | 6.4% | 0.039 / 0.132 |
| 20 | 0.0% | 9.0% | 0.030 / 0.107 |

**$N_{min}\approx 12$程度から、両側の誤分類率が10%を切り、実用に耐える
水準になる。** これは「同じボクセルを、最低12回、独立したセッションで
再訪する必要がある」ことを意味する。

#### 5.12.2 $M_{min}$・$\gamma$(§2.3.1、撤去後の追跡に必要なスキャン数)

**シミュレーション**: $M_{min}=2$、$\gamma=0.8$のもとで、撤去イベント
発生後、$P_{occ}$が閾値0.5を下回るまでに必要な追跡スキャン数を計算した。

```
撤去後、P_occ<0.5に到達するまで: 4回(miss_streakのゲート分を含めると6回)
```

**1つの「撤去イベント」を正しく記録するには、撤去した瞬間だけでなく、
その後最低6回程度、同じ場所を継続して計測する必要がある。** 撤去直後の
1〜2回だけしか追跡しないデータでは、$M_{min}$・$\gamma$の較正に使えない。

#### 5.12.3 具体的な収集計画(まとめ)

上記2つのシミュレーション結果と、既存の要件(§5.4・§5.5・§5.8・§2.7)を
統合すると、以下のような収集計画になる。

| 項目 | 目安 | 根拠 |
|---|---|---|
| 総セッション数 | 15〜20回以上 | §5.12.1($N_{min}\approx12$に、離脱・欠測分の余裕を見込む) |
| セッションの頻度 | 週2回程度 × 8〜10週間 | 総セッション数を無理のない期間に収める |
| 意図的な変化イベント | 最低3件(設置・撤去それぞれ) | §5.5④(安定/変化の両方が必要) |
| 変化イベント後の追跡 | 各イベントにつき最低6回の継続計測 | §5.12.2 |
| 1セッションあたりのパッチ数 | 5枚以上 | §2.7($N_{fit,min}$向けの相場データ蓄積) |

**この計画のうち、最も律速するのは$N_{min}$(最低12回の独立再訪)である。**
週2回×8週間で16セッションとなり、目安に届く。**もし、これほど頻繁に
再訪できない場合は、$N_{min}$自体を下げて設計し直す(その分、動的/静的
判定の精度は下がることを許容する)、という判断も選択肢になる。**

## 8. v2からの正直な評価

数式としての美しさは、v2よりさらに一段上がったと思う($P_{occ}$と
$\kappa$が同じ2数から出てくる、$\kappa$専用の重みが消える、構造ラベルの
事前分布と数式のレベルで正確に繋がる、という3点は、いずれもv2には
無かった)。パラメータの総数も、当初は「$\gamma$が増えるので横ばい」と
見込んでいたが、**実際に検算したところ$w_2$に設計不備が見つかり、
それを直す過程で$w_2$自体が不要と判明した**ため、結果としてv2の10個から
8個へと、正味で削減できた。

**さらに重要なのは、この検算によって「撤去(OCCUPIED→DECAYED)が正しく
反映されるか」という、これまで一度も定量的に確認していなかった問いに、
初めて答えられたことである(§2.6)。** 数式を作った時点では気づかなかった
「$\kappa$の非対称性」という不具合が、実際に手を動かして検算したことで
見つかり、その場で直せた。**「先に完全に定式化してから」という指摘の
価値は、まさにこの「机上で検算すれば、実装する前に不具合を見つけられる」
という点にあった**、と今回のやり取りで実感できた。今回の書き直しの
主な価値は、パラメータ削減よりも、構造的な一貫性(1組の数字からすべてが導かれる)
と、事前分布の設計との接続にあると考えるのが正直なところ。

**追記(§2.1.4〜2.1.5)**: プーリングの「滲み出し」問題は、最初
$\text{ever\_evidenced}$という素朴なゲートで直したつもりだったが、
指摘を受けて考え直すと、ドリフトの範囲内では結局同じ問題が残っていた。
最終的に、非極大抑制(近傍の中で自分が最大の時だけプーリングする)
という、**新しいパラメータを1つも追加しない**修正にたどり着けた。
これは、最初の一手が不十分だった時に、その場しのぎのゲートを追加する
のではなく、問題の構造そのものを見直したことで、より根本的で
簡潔な解決に至った例だと思う。

**追記(v4、§2.2.1)**: v3で唯一「投票箱の外」に取り残されていた
$\mu(v)$(柱2)を、$\alpha_\mu,\beta_\mu$という専用の投票箱に統一した。
これにより、実験10で見つけていた「$\mu(v)$には忘却の仕組みが無く、
一度の誤判定が永久に傷として残る」という限界を解消できた。**これで、
$P_{occ}\cdot\kappa\cdot\mu$の全てが、$\gamma$を伴う投票箱という、
同じ1つの数式パターンから導かれる形になった。** 一方、「遷移の判定
そのものは、確定($\kappa\geq\kappa_{th}$)を待ってから$\mu$に反映すべきか」
という論点も検討したが、候補(candidate)レベルで反映する代替案と
比較検算した結果、両者に有意な差は見られず、**現行(確定を待ってから
反映する)設計のままで十分**と判断した。
